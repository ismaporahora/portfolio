Carrying the brand into code

In December 2025 I redesigned Planificando's brand. When the product was rebuilt as V2 in mid-2026, I kept what worked in the interface, dropped what didn't, and wrote the rest into the product's repository as tokens and shared components. Figma and Claude Design are for exploring; the rules live in the repository, and every specimen on this page is rebuilt from it.

Role
Sole designer: identity, tokens, primitives, documentation. I open the pull requests; the tech team reviews them.

What v2 dropped

The v1 isologo and the mint accent. Mint rendered unreliably on teachers' screens in usability tests; the wordmark carries the identity alone.

Why violet

Not a taste call. Every candidate from the previous palette was tested for accessibility on teachers' real screens; violet was the only one that survived — the single UI accent by elimination.

The palette, with its rules attached

A token without a rule gets misused within a week. In this system the rule is a comment on the token itself, so it travels into autocomplete and into code review.

The success set carries four values — text, fill, border, and a separate highlight for inline diffs — because "green" used loosely is how a palette rots.

Type: one face, sized in half-pixels

Everything in the app is Figtree. Sizes are pixel-literal utilities — 12.5, 14.5, 15.5 — because at this scale a half pixel is the difference between a label that reads as a label and one that competes with the value. A serif (Source Serif) exists for exactly one surface: the reading body of the text library.

Why it lives in code

A Figma library documents intent; a component enforces it. When the owner asked for smaller buttons — “se ven un poco grandes” — the change was one constant in pill-button.tsx and every screen followed. The rules that can't be code (never mint, never white grounds, wordmark only) live as comments on the tokens themselves, so they surface in autocomplete and in code review.

I'm the sole designer and I ship the pull requests — the system is how design decisions survive without me in the room.
